# Optional research and product discovery

Research is optional in Build Flow. After exploring, suggest a scoped investigation only when an open question would
benefit from outside evidence. No fixed questionnaire, mandatory rounds or completion ceremony.

- Establish the problem, the intended outcome, constraints and current evidence. Read the code through normal
  exploration and pass the relevant context to the research worker, which only returns findings.
- The main session owns product discovery: one focused product question at a time, then wait. Never choose for the
  user or reopen settled decisions. A worker returns decision gaps to the main session instead of interviewing the user
  or inventing choices.
- Use documentation or web tools only when they are really available and allowed, preferring primary sources. Never
  assume access from a tool's name, a shell or generic MCP access, and never bypass permissions.
- Give the worker the research goal, the relevant context, the actual tool limits and these quality rules. Depth
  follows uncertainty and consequence, not a fixed number of questions or sources.
- Attribute material claims to URLs or supplied sources; separate verified facts from assumptions, contradictions,
  freshness limits and gaps. Say when tools were unavailable or claims are unsupported; never present that as done.
- Return concise findings, recommendations, tradeoffs, open questions and consequences for implementation. No separate
  proposal is needed; useful findings feed the authorized work.
- Missing, partial or contradictory research never blocks proposal work. Pause only the work that depends on an open
  product decision or unsafe missing evidence; continue independent work within scope.
- Research stays in the conversation unless the user or the task asks to keep it. The main session handles any
  authorized saving and reports failed writes honestly. Keep earlier research artifacts and notes; never rewrite or
  delete them.

## Evidence and continuing

Check the findings, their sources and the stated limits. Read back anything claimed as saved; partial research stays
useful with its gaps visible. Never invent success or evidence. Do not retry or stop just because optional tools were
missing. Continue independent authorized work and pause only the decisions that depend on missing evidence or on the
user. A transport failure is not a finding.
